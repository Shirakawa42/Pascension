# September 28 release validation

The release packages the approved balance rules and the accepted hybrid AI from
`approved-relic-pass-snapshot-1500`. It performs no training.

- Model SHA-256: `2e9d7dc1b3c65d9ac57629abfdbd7e7d0c9cd34467dddfb4e4e0fca795ff286d`.
- Model: `Assets/Resources/AI/shards-policy.bytes`.
- Runtime settings: `Assets/Resources/AI/shards-search-settings.json`.
- Metadata has a distinct resource basename to avoid shadowing the model.
- Search: 4 candidates, 24 decisions, 2 sampled public-information worlds,
  4 continuation styles, 8 workers, with the accepted tactical/menu/setup/Scry
  guards and sequence repairs enabled. No unvalidated future-Scry or shared-rollout
  experiments are included. See the JSON for the complete profile.
- Hero draft: seat-aware stable identities, updated from the same snapshot's
  75 games per ordered hero pair. Small matchup samples remain noisy.
- In-game inference uses C# on CPU, in the background, without external processes.
  The one-second presentation delay remains. CPU/GPU arithmetic is not bit-identical.

All approved rules are documented in the September 28 in-game EN/FR changelog,
the card registry and generated card table. The September 27 changes also remain
in effect. The second seat opens with five cards, one mastery and one crystal;
it does not receive six cards or two mastery. Doom Gate remains at seven defense;
Entropic Talons, Praetorian-01 and Nil Assassin have no additional buffs.

Validation before commit: 278 headless tests passed; all nine runtime assemblies
compiled against .NET Standard 2.1 and installed Unity dependency DLLs without
launching Unity. A full 297-decision game using the packaged policy/settings
matched synchronous and background execution at every decision; background
search did not mutate live state. This is an integration check, not a strength test.
The committed checkout is tested again before pushing. CI builds the actual
Windows and macOS players; no local Unity tests or simulations are run.

Known strength limitation: Volos analysis found avoidable resource spending and
Talons/heal ordering errors despite passing constructed immediate-win scenarios.
This release uses the accepted snapshot AI; those observations do not prove that
Volos needs a balance buff. Further diagnosis remains separate from this release.
